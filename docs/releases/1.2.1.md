Fixes to the review by behavior of 1.2.0, found by running it on Omaspec's own
pull requests. If you copied
[docs/ci/behavior-diff.yml](https://github.com/enhapu-afk/omaspec/blob/main/docs/ci/behavior-diff.yml),
copy it again: it runs on each push now, and takes 1.2.1 as the latest release.

## The comment on a pull request

- The workflow runs on each push to the pull request, not only on one that
  touches a diagram: once a push takes the change back, the comment says that
  no diagram changed instead of keeping the old changes.
- The machine drawn below the changes shows what came in full green and what
  changed in amber. The tints of 1.2.0 were lost on GitHub's page, light or
  dark.
- GitHub draws the Mermaid in a browser; its mobile app shows the code.

## The diff of a folder

- `omaspec diff DIR` reads the folder as git lists it, by the rules of the
  version it is compared with: what git ignores (a build, a fuzzer's corpus)
  no longer comes as new diagrams, and a submodule, a hidden folder or a file
  whose name git reads as a pattern no longer stops it. Both versions are cut
  at 5,000 files by the same rules.
- A scenario checked again because a machine changed, that Omaspec does not
  read (ZenUML, say), is no change where its text is the same.
- A line that went is named in the version it stood in:
  `agent.puml@origin/main:23`, or `old/agent.puml:23` between two folders, in
  the text and in `--json` alike; `log --json` names both versions of a
  commit (`door.puml@1a2b3c4^`, `door.puml@1a2b3c4`).
- A file whose name is not UTF-8 is read by the path git gives, and no longer
  comes in every diff.
- A folder that is gone is named in the error.

## Fixes

- A `[*]` in a note's words (`hnote over Alice : back to [*]`) no longer makes
  a scenario a state diagram.

## Install

The archives below hold the binary for x86_64 and aarch64; it runs on glibc
2.35 and newer (Ubuntu 22.04, Debian 12, Arch). Or build it:
`cargo build --release -p omaspec-app`. The guide, every function with
examples, is a [PDF](https://enhapu-afk.github.io/omaspec/guide/omaspec-guide.pdf).
