The first release after 1.0: PlantUML's sequence, activity and state diagrams
drawn without Java in every example of PlantUML's *Language Reference Guide*,
and fixes for security and crashes. Updating is recommended.

## Security

- The sanitizer drops `xml:base`. It moved every relative project link the
  sanitizer lets through to another host.
- A crafted SVG can no longer end the process on stack: elements nest 64 deep
  at most, references lead on 8 times in a row at most and never in a circle,
  and a stylesheet keeps no `url(#…)`.
- The Java PlantUML's answer to one diagram ends at 64 MiB; past that it is
  stopped as a hang is.
- The sandbox says what Landlock lacks on the running kernel, in the status
  line, as a warning from `render` and in the JSON and MCP answers.

## PlantUML without Java

Omaspec's own engines now draw 553 of the 897 examples of PlantUML's guide that
PlantUML itself draws, up from 451 just after 1.0.0. Sequence (79 of 79),
activity (62 of 62, and 13 of 13 in the old syntax) and state diagrams (36 of
36) are complete.

- **Sequence diagrams.** Slanted messages, numbers in levels, activation bars
  opened by calls, pages (`newpage`) with their numbers, participants in their
  declared order and over several lines, teoz's anchors and durations, a
  group's colors, a box inside a box, the guide's skinparams.
- **Activity diagrams.** `switch`, `backward` in a `while`, `repeat :text;`,
  connectors, hidden arrows, `detach`, notes that find their action,
  `end fork {or}`, `conditionStyle diamond`, `!pragma useVerticalIf on`,
  `package`, `rectangle` and `card` around actions, loops and choices laid out
  as PlantUML lays them out, `label` and `goto`, and the old syntax
  `(*) --> "Action"`.
- **State diagrams.** A start or an end with a name, hidden arrows, a style in
  one word (`#pink;line:red;line.bold`), notes of their own and on
  transitions, `<<sdlreceive>>`, entry and exit points on a state's border,
  gradients (`#red-green`), styles for stereotypes, `json` data among the
  states, `StartColor`, `EndColor` and the attribute fonts.
- **Text everywhere.** Creole rules and headings, `<font>`, `<back:…>`,
  `<U+…>`, wavy and colored lines; pictures with `<img:…>`, read from the
  project folder only, as `!include` is; a font for the whole diagram in
  `<style>` and one per kind of element (`ParticipantFontName`, …).

## Mermaid

- **Swimlanes** (`swimlane-beta`) drawn as bands, one for each lane.
- **Git graphs** carry out their settings, build themselves up with
  `play --build` and play commit by commit with F5.
- What Mermaid refuses is refused, not drawn as something else: a box's name
  with a space (`D --> Order parts`), a second `gitGraph`, a first line that
  names no kind. A `'` in a box's text is a letter, as in Mermaid.

## Command line and editor

- `omaspec render FILE --fold A,B` and `omaspec export DIR --fold NAME` draw
  containers folded, as the editor folds them; the MCP server's `render`
  takes `fold`.
- A scenario's notes are steps of its play, lit as its messages are.
- `play --ink --look` inks a sketch into a look of its own; `--duration` and
  `--hold` time every film.
- A refusal says why, and a diagram that starts unusually (an actor alone, a
  class with its visibility) is known by what it holds.
- An emoji in an SVG is set in the emoji faces, in color in a browser.

## Fixes

- A scenario plays every message, not only the first eight.
- A fork bar exactly as long as it must be no longer panics; the rest of what
  the nightly fuzzing found is fixed too.
- `render --fit` fits again.
- An event with a comma in its name can be taken by `--events`.
- A film starts with the play standing, not before its bar.
- Lint says that a flowchart's spacing is not carried out.

## Install

The archives below hold the binary for x86_64 and aarch64; it runs on glibc
2.35 and newer (Ubuntu 22.04, Debian 12, Arch). Or build it:
`cargo build --release -p omaspec-app`. The guide, every function with
examples, is a [PDF of 49 pages](https://enhapu-afk.github.io/omaspec/guide/omaspec-guide.pdf).
