Omaspec between AI agents and the people who steer them
([ADR 0036](https://github.com/enhapu-afk/omaspec/blob/main/docs/adr/0036-between-agents-and-people.md)):
a diagram is the contract an agent implements, a run is followed live, a pull
request is reviewed by behavior, and a finding says its fix.

## The diagram is the contract

- **The trace format is written down**, version 1:
  [docs/trace.md](https://github.com/enhapu-afk/omaspec/blob/main/docs/trace.md),
  and `omaspec trace --schema` prints its JSON Schema, so an agent or a program
  writes one without reading Omaspec's code.
- **A deviation is a task.** `omaspec trace run.jsonl --json` and the MCP tool
  `trace` give with each deviation what happened and what the machine expected
  there: the states the object could be in and the events they take, each on
  its line of the diagram.

## A run, live

- `omaspec trace run.jsonl --follow` holds a trace while it is written: each
  finding the moment its line is complete, with `--json` one object a line.
- `omaspec preview flow.puml --follow run.jsonl`, and *Follow a trace…* in the
  editor, show it on the machine: each object a pill beside the state it is
  in, a light along each transition it takes, red where it deviates.
- **Where a person decides.** `state Review <<decide>>` in PlantUML,
  `class Review decide` in Mermaid: an object standing there waits for a
  person, its pill filled, and the bar counts who waits.

## Review by behavior

- `omaspec diff --markdown` writes what changed in the behavior as a comment
  for a pull request: by diagram, each change with its file and line, and each
  state machine that changed drawn as Mermaid below, what came in green, what
  changed in amber, which GitHub draws. MCP `diff` gives the same with
  `markdown`, for the description of an agent's pull request.
- [docs/ci/behavior-diff.yml](https://github.com/enhapu-afk/omaspec/blob/main/docs/ci/behavior-diff.yml)
  is a workflow to copy: it posts that comment on each pull request and edits
  it on each push.

## Findings with their fix

- Every rule says whether its findings carry a fix, and 13 of the 36 do, up
  from 5: a block left open, a Mermaid kind misspelled, a declaration or a
  transition written twice, a participant or a lane a letter off, an icon the
  set has one name near, a text too faint on its fill. Each fix is made
  without being read first, so only where nothing is left to choose.
- `omaspec lint --fix` goes on while the fixes bring more.

## Examples and the guide

- The gallery has 49 examples: *Agents at work*, an orchestrator's workflow
  with the places a person decides, and a run of it to follow; *An agent's
  life cycle*; and *A tool call*, a scenario in Mermaid held against that life
  cycle in PlantUML.
- The guide says how an agent uses Omaspec in each of the four loops, with a
  block for a project's own `AGENTS.md`.

## Fixes

- In a scenario, `group Name {` ends with `end`, as PlantUML reads it, and is
  no longer told unclosed; a `[*]` in a message's label marks no state
  diagram.
- A state's way without an event is an option of a play, not taken the moment
  the state is entered; `play --events` names it `go on`.
- Lint says what of PlantUML's standard library Omaspec lacks
  (`!include <awslib/…>`).
- A folded subgraph says what it holds; a package's name sits in its tab.

## Install

The archives below hold the binary for x86_64 and aarch64; it runs on glibc
2.35 and newer (Ubuntu 22.04, Debian 12, Arch). Or build it:
`cargo build --release -p omaspec-app`. The guide, every function with
examples, is a [PDF](https://enhapu-afk.github.io/omaspec/guide/omaspec-guide.pdf).
