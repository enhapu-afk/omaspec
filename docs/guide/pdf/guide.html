Chapter 1First steps

Omaspec is one binary. It draws PlantUML and Mermaid with engines of its own, in a few milliseconds, without Java, a browser or a network. This chapter takes you from the install to a machine that plays.

Install

On Omarchy or any Arch Linux, from the AUR:

$ yay -S omaspec-bin        # the release's binary; or omaspec, built from source
$ omaspec theme              # the palette it reads from your Omarchy theme

Elsewhere, take the archive of the latest release (x86_64 and aarch64, linked against glibc 2.35), or build it: cargo build --release -p omaspec-app.

Start it

$ omaspec                      # the last session, or an empty PlantUML diagram
$ omaspec door.puml seq.mmd    # a tab per file; a new name is created on the first save
$ omaspec ~/diagrams           # with that folder in the sidebar
$ omaspec preview door.puml    # only the picture, drawn again on every save

Three areas share the window: the project at the left, the source in the middle, the diagram at the right. Ctrl+Alt+arrows moves between them, and a border in the accent shows which has the keys. Everything Omaspec can do is one list: Ctrl+Shift+P, then type a few letters. A tap on Alt shows a menu bar and a toolbar for the mouse.

A first state machine

  1. Write it. Type the door below into an empty tab. The picture follows a moment after each pause; nothing needs to be saved or run.
  2. Read the findings. Omaspec reads the diagram as the state machine it specifies. A state nothing leaves or one no path reaches is underlined as you type; F8 jumps to the next finding, Ctrl+. makes its fix.
  3. Play it. F5 starts the machine. Pick what happens next with 1 to 9 or a click; a light runs along each transition, ← goes back, Esc stops.
  4. Hand it on. Right-click the diagram, Export as: an SVG, PNG or PDF that carries its source, or a page that plays it in any browser.
The examples come with it. Ctrl+Shift+E lays out 49 examples as tiles, drawn on the spot in your theme: Enter opens a copy, F5 plays it. omaspec example lists them in a terminal, omaspec example coffee-machine prints one.

Chapter 2Write

The editor knows what the text means. It offers the names and events that can stand at the caret, colors a word by what it is, and says what is wrong before you look at the picture.

It draws as you type

The diagram is drawn again after a short pause, and it glides: boxes that stay move to their new places, what came fades in, what went fades out. Ctrl+Enter draws at once. An error keeps the last good picture and names its line in the status bar; a click there jumps to it.

Ctrl+click on a label, a box or a line in the diagram puts the caret on the line that draws it. The other way round, the name under the caret is lit in the picture. Lines changed since the last save are marked beside their numbers.

What the editor offers

  • Names. While you type a name, a list opens with the states or participants of the diagram. After an arrow a space is enough.
  • Events. After the colon of a transition: the events the machine takes. After the colon of a message: the events the receiver's state machine in the project takes.
  • Blocks. At the first word of a line: the words of the language for this kind of diagram, each with places to fill in. alt writes alt … else … end; Tab goes from place to place.
  • Links and members. After PlantUML's [[ the project's diagrams; after a class and :: its fields and methods.

Arrow keys choose, Enter or Tab takes, Esc closes; Ctrl+Space asks for the list anywhere. Rest the pointer on a state, an event or a participant, and a card says what it is: where it first stands, how many transitions go in and out, which events it takes.

Outline beside the source (View) shows the diagram's parts in a column: participants, states, fragments, classes. A click puts the caret on the line.

Findings while you type

A finding is underlined on its line and counted in the tab. The same checks run from omaspec lint, so a terminal, a commit hook and CI say the same words.

Labels are read as UML writes them: event [guard] / action. Each part has a color of its own in the source.

Fixes, and an even hand

A finding that can be put right in one sure way carries its fix. Ctrl+. makes the fix of the caret's line, Fix every finding that has a fix all of them as one undo step, and omaspec lint --fix does it in the files.

Ctrl+Shift+I re-indents. Prettify the diagram also sets one space around each arrow and colon and puts them in a column. Only spaces change.

Mermaid that GitHub draws too

Omaspec reads some Mermaid that mermaid.js does not, so a chart that looks right here can be a parse error in a README. Lint hints at each such line, and Rewrite for mermaid.js (GitHub), or omaspec fmt --portable, writes them the way both read.

Find, replace, rename

Ctrl+F in the sourcefind in this file; Ctrl+H replaces, Ctrl+D takes the next occurrence
Ctrl+F in the diagramfind a state, a message or any label; it lights up and comes into sight
Ctrl+Shift+Ffind in every file of the project; a hit opens its file
Ctrl+Shift+Hreplace in all tabs, each tab one undo step
F2rename the diagram, state or event at the caret at every use in the project (chapter 5)
Ctrl+Pfind a file of the folder by a few letters

Nothing is lost

The window keeps its session in ~/.local/state/omaspec/: the open tabs with their unsaved text, the folder, the caret. Closing the window loses nothing. Saving is atomic and keeps the file's line endings; a file changed on disk is loaded again while its tab has no changes of its own.

Chapter 3Shape

The layout is automatic and the look follows your desktop. Where you want it otherwise, you say so once, and what you said is written into the file as the language itself writes it.

A look for the whole diagram

Diagrams are drawn in the active Omarchy theme's colors without changing the file; Diagram theme: follow Omarchy switches to the file's own. A skin pack (Edit › Skin) writes a look into the source, as skinparam lines or a Mermaid %%{init}%%, so it stays with the file. The pane shows each pack before you choose it.

Two more packs are for paper and for a screen: spec draws strict UML in black and white, in a serif; presentation draws larger, with round corners, in one blue. The sketch look uses what both languages already have (skinparam handwritten true, Mermaid's look: handDrawn). A box takes its strokes from its name, so the same file draws the same picture every time.

A color for one box

Color this box…, in the list of commands or under the right mouse button, offers fixed colors and the theme's own for the box at the caret. The color goes into the source as the language writes it, as one undo step, so every other tool draws it too.

Lines by hand

Hold Alt over the diagram and the line under the pointer lights with its corners as dots. Alt and a drag on a straight run moves it sideways; on a dot, that corner. While you drag, the line shows exactly how it will be drawn. Alt and a double click gives the line back to the layout; Ctrl+Z takes a drag back.

Works in state, class, component, use case, deployment and object diagrams and in Mermaid flowcharts. Label to the other side moves the label of the line at the caret (Idle -> Busy label left).

Boxes held in place

Alt and a drag on a box takes its outline along, and a bar shows where it would go. Let go, and it stays beside its neighbor. No coordinates are kept, only the neighbor, so the box holds its place in any theme and font.

Fold and focus

Over a nested state, a package or a subgraph the pointer shows a small button: a click folds it to one box that says what it holds (4 states · 6 transitions). A click on the box unfolds it. Folds are the pane's, not the file's: checks and a play see the whole diagram.

Shift and a click puts a box in focus: the rest goes quiet behind a veil, and the box, its neighbors and the lines between them come through. In the editor the focus follows the caret.

Long and large diagrams

A long diagram keeps its headings in sight: a sequence diagram's participants stay at the top as small pills while the messages scroll under them, a swimlane's name stays over its lane, a Gantt chart's dates at the top. Ctrl+click on a pill jumps to the participant's line.

Chapter 4Understand

A state diagram is the state machine it specifies, a sequence diagram a scenario. Omaspec treats them that way, in PlantUML and in Mermaid alike: it checks them, runs them, and holds what a real system logged against them.

Play a machine

F5 starts it. The rest of the diagram sinks under a veil and the states the machine is in shine through. The bar below offers what can happen next; a light runs along the transition's route. Regions run side by side, a choice waits for you, a history state goes back to where its state was left. Each step lights its line in the source.

1 … 9, a clicktake that option
Spacea scenario's next message
←, Home, Esca step back, from the start again, stop

A scenario against its machines

A sequence diagram is checked against the state machines of its project. A participant named like a state diagram (door.puml, or title Door) must take every message it receives as an event, in the order the scenario sends them, through alt, opt and loop.

Lockstep. With F5 on such a scenario, the machines of its participants open beside it. As a message's light reaches its receiver, that machine takes the transition the message fires. A message the machine cannot take runs red, its state flashes and its bar says why.

Traces: did production follow the spec?

A trace is what a running system logged, one JSON object a line. omaspec trace plays it through the state machines of its project and says where the system left them, with the time.

Many objects can share one machine ("machine":"Order"), and a line may give the state the object is in. In the editor, Play a recorded trace steps through it in the diagram; where the trace deviates the bar turns red.

Coverage

How much of a machine do the traces take? omaspec coverage counts transitions and states and names each transition never taken. --min 80 fails below that share, for CI.

The same machine, seen three more ways

As a table. States down, events across, in each cell what the event does there: the classic table of a review or a test design. Two ways no guard chooses between are framed in red.

As a life cycle on a ring. The states round a circle in the order a run reaches them; a way on runs along the ring, a way back is an arc inside it, a way that skips ahead an arc outside.

As text. One fact a line, for a terminal or an agent that shows no pictures:

What changed in the behavior

omaspec diff compares two versions by states, transitions and messages, not by lines. Layout and colors do not count. With a folder it tells the whole project: every diagram that changed in its behavior, and every scenario a changed machine no longer plays.

omaspec convert door.puml -o door.mmd writes a machine or a scenario in the other language, and only when the result means the same; otherwise it says why not.

Chapter 5Projects

A folder with a file named omaspec-project.toml is a project. Its diagrams are checked against one another, link to one another by name, and make a map nobody has to draw.

Start one

$ omaspec new ~/specs/garage          # the project file and a first machine; --lang mermaid, --git

In the editor, New project asks for the language, for git or not, and for the folder. The file names the project and may pin its look, which every diagram is then drawn in: in the pane, by render, in exports and in CI alike.

pack is one of plain, spec, presentation, sketch, vivid, light, dark or auto; with light or dark the colors background, surface, text, accent, muted and note can be set, and font names the face. Without one a diagram is set in Inter, which ships with Omaspec: a picture is the same on every machine.

The map is made

Open the project file and the map stands beside it: a tile for each diagram with its picture, an arrow where a scenario plays against a machine, a state opens the diagram of its name, or a diagram includes a file. A new file is on the map as soon as it is there.

A click on a tile zooms into its diagram. In a project of more than 36 diagrams a folder becomes a tile that opens its own map.

Diagrams that link

A state named like another diagram of the project links to it and carries a mark of two small squares. A click glides into the state and opens that diagram; a trail over the diagram names the way (garage › Garage › Door). Alt+← zooms back out.

Where a name is used, and renaming it

F2 renames what the caret names (a diagram, a state, an event, a participant) at every use in the project: the machine's transitions, the messages sent to its players, the states that open it. omaspec rename Door Gate --dry-run shows what would change. Files keep their names and recorded traces are records: both are listed, not changed.

Check the whole project

omaspec check DIR is the one command for a project: lint, the scenarios against the machines, links to diagrams that are not there, entries by hand that no longer hold, and each SVG held against the one drawn now.

Compare

Ctrl+Shift+D compares the tab with another tab or with the file in a git commit: both diagrams side by side, zoomed and panned together, or the lines that changed. Compare: glide from B to A shows the change as a motion; what came glows green, what changed amber, what went fades red.

The same list offers the project since a commit or a tag: what changed in the behavior of every diagram since then. Project › History of the diagram lists the commits that changed a file and how much each changed.

Chapter 6Show

A diagram is shown, not only read. Everything Omaspec writes is one file that fetches nothing: mail it, put it in a pull request, open it offline.

The save dialog is the desktop's own. Beside the name it offers Colors: as the diagram shows, the file's own, plain, light or dark. Ctrl+Shift+C copies the diagram as a PNG.

Images carry their source. An exported SVG, PNG or presentation holds the diagram's text. Drop it on the window, or open it with Ctrl+O, and it is a diagram again; omaspec extract diagram.png prints the source. Every picture is sanitized before it is shown or written.

A talk from your diagram

Shift+F5 shows the diagram full screen in a window of its own and plays it. The editor's window becomes the speaker's: the time, where the play is, the notes of this step and of the next. The notes are the comments right above a step's line.

The keys are a presenter remote's: → Space PageDown go on, ← PageUp go back, Home starts again, 1–9 take a machine's option, F switches full screen, Esc ends.

Or hand the talk on as a page. omaspec render door.puml -o talk.html writes one HTML file that plays the diagram as the pane does, offline, with the same keys. talk.html#3 opens a scenario at its third message.

Films

omaspec play draws what the window shows, headless, and writes it as a GIF, a WebP or animated PNG in full color, or as .html: a page in vectors, sharp at any size and a fraction of a film's size.

A diagram too large to read whole is followed step by step, near enough to read; --whole keeps it whole. The bar under a play is as large as the diagram's words; --no-bar leaves it out. A note on a state comes through the veil with its state. --width, --fps, --theme, --colors and --lossy shape the file.

A project to hand on

omaspec export DIR writes every diagram as an SVG with its source, the map as index.svg, and all of it as a ZIP. Each tile and each state that opens a diagram links to that diagram's SVG, so a browser is enough to follow them.

omaspec export DIR --html writes the project as one page: its map, and a click on a tile zooms into the diagram as the editor dives into it. Esc zooms back out; the address says where the camera is (cafe.html#Day/Order).

Chapter 8In a team

Everything the editor understands is a command: for a terminal, a commit hook, a pipeline or an agent. They find the same things in the same words, with the same line numbers.

Lint and check in CI

lint, fmt --check, trace, check and render --check exit with 1 when they find something. --json gives a report for scripts, --github prints GitHub Actions annotations, --strict lets warnings fail too.

.github/workflows/specs.yml
- run: omaspec check specs --github     # lint, machines, links, pictures
- run: omaspec coverage specs/order.puml --traces logs/week.jsonl --min 80

omaspec new --git writes a pre-commit hook that runs check. Draw the SVGs once with omaspec render DIR; from then on render --check names what changed: the diagram changed since its SVG was drawn, or the same diagram is drawn differently.

Git that reads behavior

$ omaspec git setup     # once per clone; writes .gitattributes, to commit
$ git diff              # states, transitions and messages, not lines
$ omaspec log door.puml # commit by commit, what each changed in the behavior
$ omaspec diff . --rev v1.0   # the project since a tag: a changelog of the spec

After the setup, git diff, git log -p and git show compare a machine's states, transitions and findings and a scenario's messages. A change of layout or color is no change; --no-textconv shows the lines.

Markdown documents

A .md file is a document of diagrams. Every fenced block that names plantuml, puml, mermaid or mmd is highlighted in its language, linted and checked on the document's lines. The pane draws the diagram the caret is in.

$ omaspec lint README.md      # each block, on the document's lines
$ omaspec render README.md    # one image per block: README-1.svg, README-2.svg
$ omaspec fmt --write README.md   # each diagram in its place, the prose as it is

AI agents

omaspec mcp is a Model Context Protocol server over standard input and output. An agent lints a diagram, holds a trace against the machines of its project, compares, converts and renders, getting a PNG back to look at. Nothing goes over the network.

$ claude mcp add omaspec -- omaspec mcp
# any other client: {"mcpServers": {"omaspec": {"command": "omaspec", "args": ["mcp"]}}}

The tools are the command line's: lint, trace, coverage, matrix, refs, inspect, outline, diff, convert, format, render. Every finding carries a code a program can rely on (chapter 10). Where agent and person meet, four loops:

The diagram is the contract. The person writes or approves the machine; the agent implements it and lets the system write what it does as a trace (omaspec trace --schema). A deviation comes back as a task: what happened, and what the machine expected there, each on its line of the diagram.

A run, live. An orchestrator appends a line for each step to a file; omaspec preview flow.puml --follow run.jsonl shows each agent where it stands, filled where it waits for a person (state Review <<decide>>), red where it deviates. omaspec trace run.jsonl --follow --json says each finding the moment its line is written.

Review by behavior. Before it hands its work over, the agent puts what came, changed and went into its pull request, each changed machine drawn as Mermaid, which GitHub draws; docs/ci/behavior-diff.yml posts the same as a comment on each push.

Findings it acts on alone. A finding that can be put right in one sure way carries its fix, in lint --json and MCP lint: 13 of the 36 rules have one. What is left is the writer's choice, and there the agent asks, as the gallery's A tool call does: a scenario in Mermaid held against An agent's life cycle in PlantUML.

Chapter 9Omarchy

Omaspec is made for Omarchy. It follows the theme and the font while it runs, uses the desktop's own dialogs, and comes with what Hyprland needs.

Themes and fonts

The editor and the diagrams follow omarchy theme and omarchy font set live. Every bundled theme is tested to read: each text at 4.5:1 against what lies under it, each line at 3:1. A faint color (a yellow on white) is deepened just enough.

Hyprland

Templates are installed to /usr/share/omaspec/omarchy:

  • hyprland.lua: Super+Shift+U opens the editor; window rules for the diagram windows are commented there.
  • omarchy-menu.jsonc: a Diagram editor entry for the Omarchy menu.
  • omaspec.toml.tpl: copy it to ~/.config/omarchy/themed/ to set the syntax and mark colors per theme.

Window classes for rules: omaspec (the editor) and omaspec-preview (the preview window, and the editor's diagram in a window of its own). Copies and exports send an Omarchy notification. On a laptop with two graphics cards Omaspec draws with the frugal one; WGPU_POWER_PREF=high omaspec takes the strong one.

The preview window, beside Neovim

omaspec preview flow.puml is a window that draws the file again on every save. Edit in Neovim, or anything else, and keep it tiled beside. An error shows in its status bar while the last good picture stays.

Findings by their code

Every finding in a --json report and from the MCP tools carries a code. A program reads the code, not the message: the code stays, the words may change.

refusedPlantUML or Mermaid does not take the diagram as written
